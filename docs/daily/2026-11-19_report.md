**추가 지시: API 비용 상한 100달러를 코드에 걸었다.**

- `configs/analysis.toml`에 프로젝트 전체 상한 100달러를 적고, 모든 모델 호출이 거칠 사용량 장부(`analysis/budget.py`)를 만들었다(PR #15).
- 호출 전에 최악의 경우 비용(입력 추정 상한 + 출력 상한)을 누적액에 더해 100달러를 넘으면 호출하지 않는다. 요금표에 없는 모델도 호출하지 않는다.
- 이 상한은 계획서의 "월 2만 원" 기본값을 대체한다. D3 작업 6의 상한 2달러는 그대로 두었으나 호출이 없어 쓰지 않았다.
- **이 제한은 이 프로젝트의 코드가 스스로 지키는 제한이다.** 장부는 Git에서 제외된 로컬 파일이라 지우면 누적액이 0이 되고, 다른 프로그램이 같은 키를 쓰면 막지 못한다. 계정 차원의 한도는 Anthropic Console의 사용 한도 설정에서 직접 걸어야 한다(내가 대신 할 수 없다).

**holdout 사례 구성 (10개)**

| 유형 | 수 | 사례 | 결함 종류 |
|---|---|---|---|
| `log_clear` | 2 | 101, 102 | 자료형 변환, 예외 처리 누락 |
| `needs_related_code` | 3 | 103, 104, 105 | 종료일 비교, 정렬 방향, 계산 기준 금액 |
| `distant_cause` | 2 | 106, 107 | 파싱 필드 뒤바뀜, 영업일 계산 |
| `insufficient_evidence` | 2 | 108, 109 | 요구사항 불명, 러너 로캘 의존 |
| `out_of_scope` | 1 | 110 | 테스트 통과 후 빌드 단계 실패(`not_test_failure`) |

- 정답을 먼저 커밋한 뒤 실패 실행을 만들었다. 10건 모두 정답에 적은 테스트만 실패했고, 재실행이나 오염은 없었다.
- 결함은 전부 dev 사례가 건드리지 않은 모듈과 워크플로에 있다. 테스트 데이터는 바꾸지 않았다(승인 항목 미사용).

**계획과 달라진 점**

- **`insufficient_evidence` 2건의 성격:** dev의 외부 데이터 계열을 피하려고 "요구사항이 입력에 없음"(108)과 "실행 환경 값이 입력에 없음"(109)으로 만들었다. 두 사례 모두 낮은 확신의 원인 후보도 정답으로 허용한다. 특히 109는 코드에 로캘 의존이 보이므로 분석이 후보를 맞힐 가능성이 높고, 판단 보류를 요구하는 사례로는 약하다.
- **파일 선택 규칙의 결함을 테스트가 잡았다.** 저장소 밖 라이브러리 파일과 이름이 같은 저장소 파일을 traceback 파일로 잘못 고르는 경우였다. 병합 전에 고쳤고, 정답을 보고 고친 것이 아니다.
- **로그 정리를 추가했다.** 줄마다 붙는 작업·단계 이름, 타임스탬프, 색상 코드를 떼고 제공한다. 줄 번호는 원본과 같다. 계획서에는 없던 항목이다.
- **의존성 `pydantic`을 추가했다.** 보고서 스키마 검증과 D4의 구조화 출력에 쓴다.

**미리 확인한 결과: 방식 B의 규칙은 dev에서 원인 파일을 9건 중 5건 포함한다.**

- 놓친 4건(002, 003, 008, 010)은 실패가 단언문에서 드러나 traceback에 테스트 파일만 나오는 사례다. 표는 [analysis_methods.md](../analysis_methods.md)에 있다.
- 계획서에 적은 대로 이 결과를 보고 규칙을 고치지 않았다. 방식 C와 비교할 B의 한계로 남긴다.
- 입력 크기는 사례당 약 2만 3천~3만 글자이고 대부분이 로그다. 토큰 수는 실제 호출 전이라 모른다.

**확인이 필요한 사항**

- **holdout을 개발 중 한 번 읽었다.** 묶음 읽기 기능이 실제 묶음에서 동작하는지 확인하면서 case-107의 묶음을 열었다. 줄 수와 한 줄을 출력했을 뿐이고 프롬프트나 규칙 조정에 쓰지 않았지만, dev 묶음으로 했어야 했다. 이후 확인은 dev 묶음으로만 한다.
- dev와 holdout을 같은 사람이 이틀 사이에 만들었다. 결함 종류는 나눴지만 작성 습관이 겹칠 수 있다.
- PR은 스쿼시 병합이라 `main` 이력에서는 "정답 먼저" 순서가 한 커밋으로 합쳐진다. 순서는 PR #13의 커밋 목록에 남아 있다.
- 사용량 장부의 입력 토큰 추정(2바이트당 1토큰)은 한글이 많은 입력에서는 실제보다 적게 잡을 수 있다. 현재 입력은 영문 로그와 코드라 문제가 없고, 실제 사용량은 호출 후 응답의 값으로 기록한다.
- 캐시 토큰 요금은 측정값이 없어 보수적으로 잡았다(쓰기 1.25배, 읽기 할인 없음).
