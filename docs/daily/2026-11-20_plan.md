**작업 항목**

| # | 작업 | 산출물 | 완료 기준 |
|---|---|---|---|
| 1 | 모델 호출 모듈 | `analysis/runner.py`, 시스템 프롬프트 v0 (`src/` 안) | 가짜 응답으로 형식 오류·인용 오류·상한 초과 경로를 테스트. 모든 호출이 사용량 장부를 거침 |
| 2 | 분석 CLI | `scripts/analyze.py <input_id> --method A\|B` | 보고서와 `manifest.json`(입력 해시, 모델, 프롬프트 해시, 선택 파일, 토큰, 비용, 검사 결과)을 `work/runs/`에 저장 |
| 3 | 첫 실제 호출 | dev 사례 1건(case-009) × A/B | 형식·인용 검사 통과. 실제 토큰 수와 비용을 측정해 예상치와 비교 |
| 4 | dev 전체 1차 실행 | 분석 가능한 dev 11건 × A/B = 22회 | 원본 응답과 검사 결과 저장. `out_of_scope`(case-012)는 모델 호출 없이 사유 코드로 처리됨을 확인 |
| 5 | 1차 결과표 | `outputs/`의 표: 사례별 결론 유형, 형식·인용 검사 통과 여부, 토큰, 비용 | 코드로 판정 가능한 항목만 채움. 원인 일치 여부는 빈칸으로 두고 채점 방법을 D5 계획에 올림 |
| 6 | D4 보고서와 D5 계획서 | `docs/daily/` | 아침 보고 전에 병합 |

- holdout 사례는 실행하지 않는다.
