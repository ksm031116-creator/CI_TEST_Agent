**계획과 달라진 점**

- **입력에서 정답 힌트가 새는 문제를 발견해 고쳤다.** 평가 사례의 브랜치 이름이 심어 둔 결함을 설명하고 있었고(예: `case/008-bulk-off-by-one`), 실행 정보와 로그 8줄에 그대로 들어갔다. 첫 호출에서 모델이 브랜치 이름을 보고서에 언급한 것을 보고 알았다. 브랜치 이름을 실행 정보에서 빼고 로그에서는 `<branch>`로 바꿨다(PR #19, #20). dev 전체 실행은 고친 뒤에 했다.
- **고치기 전의 호출 2회는 결과에서 뺐다.** 비용 0.19달러는 장부에 그대로 남아 있다.
- **프롬프트 v0를 dev 실행 전에 한 번 바꿨다.** `<branch>` 표기를 설명하는 문장을 추가했다. 결과를 보고 고친 것이 아니라 버전은 v0로 두었고, 프롬프트 해시로 구분된다.
- **API 비용 상한을 85달러로 낮췄다**(PR #17, 추가 지시).
- **실행 폴더의 시각은 UTC+9 고정 오프셋으로 계산한다.** Windows의 Python에 시간대 데이터가 없어서다.

**내가 정한 것 (확인이 필요하면 알려 달라)**

- **보고서 언어:** 서술은 한국어, 인용·식별자·경로·명령은 원문 그대로 쓰게 했다. 계획서에 없던 결정이다.
- **구조화 출력 사용:** API가 보고서 JSON 구조를 강제한다. 그래서 "형식 검사 통과율"은 JSON 문법이 아니라 결론 유형과 구성의 일치 여부만 잰다.
- **추론 강도:** 모델 기본값인 `medium`을 설정 파일에 명시했다. 출력 상한은 8,000 토큰 그대로다.
- **잘리거나 거부된 응답은 재요청하지 않는다.** 같은 입력과 상한으로 다시 요청해도 같은 결과가 나올 가능성이 높아서다.
- **작업별 상한은 누적액 기준이다.** `--ceiling-usd 10`은 "장부 누적액이 10달러를 넘을 수 있으면 호출하지 않는다"는 뜻이다.

**확인이 필요한 사항**

- **dev 실행의 `manifest.json`에 `dirty: true`가 찍힌 실행이 있다.** 실행 중에 아직 커밋하지 않은 `scripts/summarize_runs.py`를 작업 폴더에 만들었기 때문이다. 분석 코드와 설정은 커밋 `14e8ce7`과 같다. 최종 평가에서는 변경 사항이 없는 커밋에서만 실행한다.
- **채점 기준이 아직 문서로 없다.** "일치/부분/불일치"는 결과표를 만들면서 임시로 정했다. 특히 원인을 맞게 추정하고도 보류로 결론 낸 경우(case-008)의 처리가 정해지지 않았다. D5 계획에 올렸다.
- **근거가 주장을 실제로 뒷받침하는지는 보지 않았다.** 인용 검사는 인용한 줄이 존재하는지만 확인한다.
- **holdout 사례의 브랜치 이름도 결함을 설명한다.** 같은 가림 처리가 적용되므로 따로 고칠 것은 없다. holdout 묶음은 열어 보지 않았다.
- **계정 차원의 한도는 확인하지 못했다.** 코드의 85달러 제한은 이 프로젝트만 막는다.
