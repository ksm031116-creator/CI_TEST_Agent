**계획과 달라진 점**

- **모델 호출 8회를 "탐색 6회 + 보고서 1회 + 재요청 1회"로 나눴다.** 계획서는 "마지막 호출은 도구 없이 보고서"였다. 그대로 두면 마지막 호출의 보고서가 검사에 실패했을 때 고칠 기회가 없다. 설계 문서에 반영했다.
- **실행당 비용 한도는 예상으로 판단한다.** 다음 호출의 비용을 미리 정확히 알 수 없어, 직전 호출의 토큰 수로 어림한다. 실제 비용이 0.60달러를 조금 넘을 수 있다. 이번 실행의 최대는 0.386달러였다.

**내가 정한 것 (확인이 필요하면 알려 달라)**

- **검사 실패 뒤의 재요청은 도구 없이 받는다.** 재요청에서 다시 탐색을 시작하면 끝을 보장하기 어렵다.

- **방식 C의 "첫 응답 검사 통과"는 첫 보고서 응답을 기준으로 센다.** 도구를 부른 응답은 보고서가 아니기 때문이다.
- **case-002 C를 "일치"로 채점했다.** 같은 설명을 한 방식 B의 판정에 맞췄다. 검토 요청의 묶음 1과 함께 봐 주시면 된다.

**확인이 필요한 사항**

- **채점 7묶음의 검토가 계속 남아 있다.** 방식 C 11건도 미검토다. [dev_grading_review.md](../../outputs/dev_grading_review.md)에 방식 C의 경계 판정 1건을 더했다.
