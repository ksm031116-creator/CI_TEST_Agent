**계획과 달라진 점**

- **작업 1을 하지 못했다.** 검토 답이 없었다. 결과표는 계속 "미검토"다.
- **두 버전 사이의 변경 내역을 보는 도구는 넣지 않았다.** 프로젝트 계획서의 도구 목록에는 있다. 입력 묶음에는 스냅샷이 하나뿐이고, 이전 버전을 주면 바뀐 곳이 곧 정답에 가까워져 A/B와 같은 자료에서 출발한다는 전제가 깨진다. 설계 문서에 사유를 적었다.

**내가 정한 것 (확인이 필요하면 알려 달라)**

- **방식 C는 방식 A의 자료(로그만)에서 출발한다.** B와 C의 차이를 "코드를 누가 고르는가" 하나로 만들기 위해서다.
- **검색은 정규식이 아니라 문자열 일치다.** 모델이 쓴 패턴을 실행하지 않는다.
- **`read_file`은 호출당 200줄까지다.** 12회를 다 써도 최대 2,400줄이다.
- **오류로 끝난 도구 호출도 한도에 센다.**
- **코드 근거는 도구가 실제로 보여 준 줄만 인용할 수 있게 한다.** 줄 단위로 기록해 두었고, 검사는 D7에 붙인다.

**확인이 필요한 사항**

- **채점 7묶음의 검토가 아직 남아 있다.** 방식 C의 결과도 같은 기준으로 내가 1차 채점하게 되므로, 검토가 없으면 A/B/C 비교 전체가 "미검토"로 남는다.
- **방식 C의 실행당 비용은 아직 어림이다.** 8회를 다 쓰면 약 0.59달러, 3~5회에 끝나면 0.25~0.40달러로 본다. D7 계획에 실측을 먼저 하도록 넣었다.
- **도구 사용과 보고서 스키마 강제를 한 호출에서 함께 쓸 수 있는지는 확인하지 못했다.** D7의 첫 호출로 확인한다.
- **CLIProxyAPI는 쓰지 않는다.** 구독 인증을 다른 도구에서 쓰는 것이 금지돼 있고 2026년 4월부터 막혔다고 보도됐다. 지금처럼 API 키와 사용량 장부로 진행한다.
